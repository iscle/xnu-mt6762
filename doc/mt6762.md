# MT6762 experimental port

This branch starts at Apple's `xnu-8796.121.2`
(`c54f35ca767986246321eb901baf8f5ff7923f6a`). It is an early bring-up,
not a working iOS phone port. No physical phone has been booted or flashed.

## Source provenance

The first import applies `xnu/redwood.patch` and `xnu/files` from
[HackiOS d82c64a3](https://github.com/oosexgang/hackios-xnu-kernel/tree/d82c64a3a31cd27a0a0afbf6e213e467e44b1b4c).
It retains that project's filesystem, generic GICv3/PSCI, Linux build support,
and replacement driver interfaces. Its Qualcomm peripheral drivers are not
MT6762 drivers. Preserve the original licenses and attribution.

The Cortex-A53 commpage adaptation draws on patch 0080 from
[ios-sailfish 6f27e41f](https://github.com/joranv1/ios-sailfish/tree/6f27e41ff249f2680540ebe8ee5ab982c5e641c9).
Here a failed exclusive store returns failure immediately: the preemption-free
zone must not contain a backwards retry loop. The unavailable trust-cache
service handling adapts that project's patch 0015 and returns not-found or
not-supported; it does not manufacture valid trust-cache results.

## Donor userspace

Selected bring-up donor: **iPhone X iOS 16.5 (20F66), iPhone10,3 / iPhone10,6**,
`iPhone10,3,iPhone10,6_16.5_20F66_Restore.ipsw`. This matches the HackiOS
kernel/userspace baseline and Linux build workflow. Its Apple-CDN
BuildManifest was checked for product, version, build, and OS/cryptex paths.
This selection has reached SpringBoard's home screen on the Cortex-A53 QEMU
model. It does not mean the IPSW supports MediaTek hardware directly.

Apple executables and dyld caches are precompiled inputs. The work adapts the
kernel and separately built support programs around them; Apple userspace is
not rebuilt. Mach-O arm64 subtype alone does not prove every executable path
is supported by Cortex-A53. Execution tests remain necessary.

## Page sizes and ISA

MT6762 uses Cortex-A53. The target does not enable PAN, LSE, or the 16 KiB
hardware translation granule. It compiles with `-mcpu=cortex-a53` and uses
bounded LDAXR/STXR commpage trylocks when ARM PFZ is enabled. The tested
configuration disables ARM PFZ, so that assembly adaptation is not linked
or execution-tested in the reported boot.

**VM pages are 16 KiB; hardware translations are 4 KiB.** `arm_init` selects
`PAGE_SHIFT_CONST=14`, including on boards with 1 GiB or less, while
`ARM_PGSHIFT=12`. Existing XNU `PAGE_RATIO=4` pmap code emits four PTEs for
each VM page. This is the mechanism Apple describes for
[A7/A8 iOS memory](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/ManagingMemory/Articles/AboutMemory.html).
No hypervisor is required for this configuration. It is not native 16 KiB
hardware paging and does not claim to run an unchanged 16 KiB-pmap kernel.

Observed on the Cortex-A53 QEMU model:

```
MT6762: VM page=16384 hardware page=4096 TCR_EL1=0x22a51a251a
```

The model also reports `ID_AA64MMFR0_EL1=0x1122`, whose TGran16 field is zero.
The real CPU's exported MIDR is `0x410fd034`, matching the model. The real
MMFR0 granule fields have not been sampled.

## Hardware evidence and initial support

The supplied dump contains an Android boot v2 image, a gzip AArch64 Linux
4.19.191 kernel, an embedded IKCONFIG, and a DTB inside an Android DT table.
The DT family compatible is `mediatek,MT6765`; eight Cortex-A53 CPU nodes
use affinities 0..3 and 0x100..0x103. The provided BSP is older than the dumped
kernel and is a register/API reference, not the exact stock source.

| Resource | Observed description |
| --- | --- |
| RAM | Base 0x40000000; historical boot records report 6 GiB; live Linux MemTotal 6017036 KiB after reservations. Static DT's 512 MiB is a placeholder. |
| GICv3 | GICD 0x0c000000, GICR 0x0c100000 |
| Architectural timer | 13 MHz, virtual timer INTID 27 |
| UART0 | 0x11002000, 32-bit registers with shift 2, INTID 123 |
| UART1 | 0x11003000, INTID 124 |
| PSCI | SMC |
| Display configuration | AXS15260, 384 x 854, from compiled kernel config |
| Touch | AXS on I2C0/address 0x3b; physical drag observed on axs_ts input |
| Panel bias | I2C5/address 0x3e |
| Charger / PMIC | PSC5425E, I2C5/address 0x6a / MT6357 |
| Buttons | Physical volume up/down on mtk-kpd; power on mtk-pmic-keys |
| GPU configuration | PowerVR RGX family |

The overlay includes inconsistent reference panel/touch entries. Do not use
those entries to claim the actual panel is the reference FHD/Goodix hardware.

The live display service reports 384 x 854 at 60 Hz. Its application-buffer
format does not establish the bootloader's physical scanout address/format.
Historical LK framebuffer base 0x7ef90000 still needs current handoff validation.

The XNU UART driver only uses the MT6577-compatible polled register subset.
It preserves firmware baud/clock/pinmux setup. GIC and PSCI are adapted from
the generic reference implementation. First experiments use one CPU.

## Validation boundary

A locally built QEMU `mt6762` machine models enough hardware to execute the
exact stock Linux Image and to start this source-built XNU. XNU has reached
VM initialization, scheduler initialization, IOKit platform/CPU registration,
BSD initialization, original Apple launchd/dyld, backboardd and SpringBoard.
The home screen renders in a RAM framebuffer at 384 x 854 with software
rendering. An emulated wake/button/swipe sequence was needed after startup;
this does not exercise physical input. Some widgets remain blank and the
battery indicator is a placeholder. No broad application compatibility claim
is made. The original executable/cache hashes were compared against the
retained Apple DMGs and actual emulator root images.

The home-screen observation initially used kernel SHA-256
`5e761b37377c35f0f0782609dcb954f05e9db08ba9a1245a83db0435ad8ff8e3`.
The subsequent guard against Qualcomm peripheral initialization produced
`3ff8137fb613c2c7991704cc29b63e82879b80445efaa2d62fc58cbd6d6ed622`;
its separate smoke test reached Apple launchd/SpringBoard and rendered the
boot logo, and a subsequent GUI run rendered the home screen around 340
seconds. The initializer's disassembly confirms no calls to Qualcomm
touch/button/battery setup. The final platform source is commit `026b4cb`.

The kernel links, but the donor's export/symbolset post-link checks fail.
`tools/mt6762/build.sh` records that distinction and rejects unrelated build
failures; the result is not a fully passing upstream XNU build.

The stock Linux Image reaches its init kernel thread in the model, then
stops at unmodeled TOPRGU/DFD hardware. Full Android boot is not achieved.

The source port inherits research stand-ins for Apple security and driver
services, including injected activation/setup and renderer shims from the
pinned reference. Original executable bytes do not mean unchanged runtime
behavior or a stock restored iOS installation. The port does not implement
Apple's production security model.

Real hardware still needs a bootloader handoff based on the live RAM map,
reserved regions and watchdog state, plus MediaTek display, storage, input,
power and other drivers. The Qualcomm/Adreno implementations do not provide
those functions for this PowerVR/MediaTek board.

## Mandatory physical acceptance criteria

These are requirements, not optional future features. None is satisfied by
an emulator framebuffer or a portable protocol test alone.

| Requirement | Available work/evidence | Remaining native work |
| --- | --- | --- |
| Display and brightness | Native OVL0/DSI handoff validation, PWM control and AppleARMBacklight interface; synthetic native boot passes | Real reserved scanout/clock/pin handoff, CoreBrightness runtime acceptance, cold initialization, blank/unblank |
| Touch | Native I2C/APDMA polling, AXS0007 validation and event delivery; synthetic queue and fault-release tests pass | Real rails/pad/ownership handoff, physical multitouch and iOS input validation |
| Power/volume buttons | Physical Android mapping; native PWRAP/keypad sampling, debouncing and queue delivery | Native PMIC/keypad emulator and physical validation, wake and power handling |
| Battery and charging | PSC5425E transport, disable/readback, thermistor table and nominal conversion | Calibrated ADC/gauge, source detection, verified voltage/current limits, temperature/watchdog policy and physical charging tests |
| CPU/peripheral clocks and PMIC | Native I2C clock/gate checks; CPU/CCI/rail/PVT readback; bounded SSPM liveness transport; all eight emulated cores online | Real handoff, coordinated frequency/voltage governor, thermal limits and firmware-managed idle |
| DMA | Native private contiguous pages, 33-bit bounds, cache ownership and APDMA; queue/fault tests pass | Physical coherency/IOMMU/ownership verification and stop/reset recovery |

The real CPU policies expose maxima 2.001 GHz for CPUs 0–3 and 1.5 GHz for
CPUs 4–7, rather than the generic DT's higher figures. Best performance means
using the supported operating points with coordinated shared VPROC/VSRAM
rails and thermal controls. The stock firmware uses hybrid SSPM DVFS; blindly
programming independent PLLs/voltages would bypass that coordination.

The stock exported battery temperature is hardcoded to 25 C. A separate ADC
path provides actual thermistor readings, but compensation and calibration
still require validation. Copying the constant into a charging policy would
not provide temperature protection. Details, exact binary locations and
testable protocol code are under `tools/mt6762/hardware/power`.

The AXS driver uploads firmware through erase/write/check operations in the
stock kernel. The extracted firmware is kept outside Git; no automatic
controller flash is part of this port. Native implementations and their
explicit ownership requirements are described in [mt6762-native.md](mt6762-native.md).
Their emulator tests remain separate from mandatory physical acceptance.

## Reproduction

`tools/mt6762/bootstrap.sh` prepares isolated pinned build dependencies;
`build.sh` links XNU and reports its validation boundary.
`prepare-ios.sh` fetches the selected donor and builds the project-owned
support programs; `verify-ios.py` checks original Apple executable/cache bytes.
The optional launchd-job filename fix is a patch to the donor's Python build
script, not to an Apple binary.

`tools/mt6762/run-ios.sh` stages a private root image and runs the bounded
software-rendered GUI experiment with synthetic input and framebuffer captures.
It defaults to the freshly built kernel, one emulated CPU and 4 GiB of model
RAM. It takes several minutes to reach the home screen. These parameters are
laboratory settings, not the phone's native SMP/memory configuration.
`tools/mt6762/test-host.sh` runs loader and portable hardware-protocol tests;
passing it is not physical acceptance.

`tools/mt6762/qemu/README.rst` explains how to replay the local QEMU fork.
`tools/mt6762/boot/prepare.py` produces an emulator-only loader/ADT/segments,
and `capture.py` captures its actual RAM framebuffer. The synthetic memory
layout is not a phone boot image. Native reserved memory, firmware services,
storage and bootloader handoff remain prerequisites for a physical trial.
Passive ADB reports a production user build, `ro.debuggable=0`,
`ro.boot.flash.locked=1` and verified-boot state `green`. A temporary custom
kernel entry path has not been established. No bootloader unlock, reboot,
flash, privilege escalation or raw register write was attempted. The ordinary
ADB shell cannot read several required regulator/clock/scanout details.

Build artifacts, SDKs, IPSW contents, firmware dumps, and device-specific
private partitions must stay outside version control.
