I2C5 capture31 setup profile and bounded PSC observation
=======================================================

Capture31 establishes actual post-write I2C5 behavior independently of bus0.
The previous capture26 peripheral record is the inherited entry state; it
must continue to pass ``mt6762_charger_entry.h`` before any bus5 setup. The new
``mt6762_charger_setup.h`` accepts only the separately observed result of
programming parent index2 / 124800000Hz / requested 100000Hz:

============== ========== ==========
Field          Programmed Read back
============== ========== ==========
CLK_DIV        0404       0004
TIMING         0419       0419
LTIMING        0118       0118
HS             0000       8000
IO_CONFIG      0003       0003
EXT_CONF       8001       8001
DELAY_LEN      000a       000a
TIMEOUT        0190       0190
============== ========== ==========

These are exact 16-bit comparisons, not masks that admit unobserved dividers,
rates or HS bits. Both the requested timing structure and all eight actual
readbacks must match. Shared parent/PLL/gates and dedicated I2C5 gate bits
18/19/20 at INFRA0xc8 must also remain valid. The bus0 matcher is unchanged
and is never selected for bus5. Entry TIMING0418/IO01a3/TIMEOUT0000 cannot pass
the new post-write matcher.

Kernel consumer contract
------------------------

The existing inherited entry checker still runs before shared gate writes and
again immediately before bus5 setup. A previously refused entry cannot be
repaired by shared clock operations. After exact setup validation there are
two explicitly selected physical modes:

* ``charger-setup-only=1`` always leaves the engine unavailable and permits
  zero transactions, including when ``charger-readonly-probe`` is also set.
  Its existing compiled SETUP_ONLY marker and diagnostic log format remain.
* ``charger-readonly-probe=1`` requires ``charger-inherited-probe=1``,
  ``i2c5-verified=1`` and ``pwrap-inherited-probe=1``. Normal charger grants
  ``charger-verified``, ``charger-control-owned`` and ``pwrap-write-owned``
  must all be absent/zero. Missing/conflicting modes reject before controller
  setup. The ordinary parent, DMA and pad handoff requirements still apply.

Inherited entry alone is not a general bus5 transaction grant. The new
read-only mode latches a private restriction in ``native_bus``. The transfer
wrapper permits only six combined transactions to address0x6a, each with one
register-pointer TX byte and one RX byte, in exact order 3,1,0,3,1,0. This is
the existing ``mt6762_psc_observe`` ID/control/status sequence twice.
Every other address, register, order, shape, pure write/read and transaction
beyond six is rejected before touching the controller. Display-bias address
0x3e and CE-disable/charge-enable writes cannot pass this interface.

An attempted transfer consumes its slot before entering the engine. Any
negative result, short/excess message result or engine fault makes the bus
fault sticky and blocks retry. Successful completion must report exactly two
messages. Each attempt logs its index, register, result and successful raw
byte, retaining unexpected ID evidence even when the PSC observer rejects it.
After six attempts readiness is withdrawn. Dedicated gates are rechecked on
each eligible transaction even if the handoff flag later changes; the private
mode remains latched. The canonical engine uses FIFO for these one-byte pairs,
not DMA, and performs its existing bounded repeated-START protocol.

Only after a valid read-only setup, outside the setup-only return, the kernel
emits this exact compiled marker for a future producer compatibility check::

  MT6762_PSC_READONLY_ADMITTED transactions=6

``power.c`` already requests the two observations only inside its inherited
PWRAP probe branch. It validates IDf0 before reading control/status and never
enters normal charger policy from that branch. No power-driver change or
charge-control grant is added here. The producer must supply a separately
requested read-only option; this consumer change does not enable it by default.

This means no charger register-data write, not electrical passivity: the PSC
datasheet notes that reads can refresh its OTG watchdog. Identity, actual
control/status, CE-disable readback, charging policy and independent protection
remain unverified until their own observations/implementations. No physical
read-only PSC probe was performed by this change.

Validation
----------

``test_charger_setup.py`` compiles the actual native initialization, readiness
and transfer wrapper with controlled MMIO and the real timing calculator.
It covers every bit of all eight post-write fields, profile rates, missing or
conflicting mode grants, both simultaneous modes, all dedicated gates,
setup-only isolation even with engine-ready bits changed, two actual PSC
observer calls, wrong identity, every transfer failure position, all short/
excess completion counts, no retry, no control/bias transactions, budget
exhaustion, and unchanged bus0/synthetic behavior. The host engine callback
checks message shape; it does not claim a physical repeated-START result.

``test_charger_postsetup.c`` separately checks all programmed timing bits and
every address/register combination at every allowed sequence index, transfer
lengths, missing buffers and exhausted/overflowed indices. The kernel source
identity test covers the new shared setup header. Both tests are included in
``sh tools/mt6762/hardware/power/test.sh``. No kernel header/IIG layout, builder,
boot image or device state was changed by this scoped consumer implementation.
